# CRM: учёт звонков и назначение встреч

REST API на FastAPI + SQLite для отдела продаж: компании, звонки, встречи и
расписание менеджеров. Интерфейса нет, только API (Swagger — `/docs`).

## Стек

- Python 3.12, FastAPI, Pydantic v2
- SQLite + SQLAlchemy 2.0
- pytest + httpx (тесты)

## Запуск одной командой

```bash
docker compose up --build
```

Сервис: <http://localhost:8000>, документация: <http://localhost:8000/docs>.
Данные SQLite сохраняются в docker-volume `crm-data`.

### Локальный запуск

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --reload
```

### Тесты

```bash
pytest -q
```

Тесты используют отдельную временную БД и не затрагивают `crm.db`.

## Эндпоинты

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/companies` | добавить организацию |
| GET | `/companies?status=&limit=&offset=` | список с фильтром и пагинацией |
| POST | `/calls` | результат звонка |
| POST | `/meetings` | назначить встречу менеджеру |
| PATCH | `/meetings/{id}` | перенести (`start_time`) или отменить (`status=cancelled`) |
| GET | `/managers/{id}/schedule?date=YYYY-MM-DD` | расписание менеджера на день |
| GET | `/meetings/{id}` | встреча с историей изменений |
| POST/GET | `/managers` | вспомогательное: менеджеры (нужны для расписания) |
| GET | `/health` | healthcheck |

Статусы компании: `new` (по умолчанию), `no_answer`, `refused`,
`meeting_set`. Статус обновляется последним результатом звонка.

### Формат ошибок

Все ожидаемые отказы возвращают 4xx и JSON:

```json
{
  "error": {
    "code": "meeting_conflict",
    "message": "У менеджера уже есть встреча с 15.03.2027 10:00 по 15.03.2027 11:00 (Asia/Almaty)"
  }
}
```

Для ошибок валидации добавляется `details` со списком полей. Коды ответов:

- `404` — компания/менеджер/встреча не найдены;
- `409` — пересечение встреч, повторная отмена, перенос отменённой встречи;
- `422` — невалидные данные: рабочие часы, выходной, naive-время,
  `meeting_set` без встречи, неверный БИН/телефон и т.п.

## Бизнес-правила

1. Длительность встречи всегда 60 минут; `end_time` вычисляется сервером.
2. Встреча целиком должна попадать в пн–пт 09:00–18:00 **Asia/Almaty**.
   Например, 17:00–18:00 разрешена, 17:30–18:30 — нет. Выходные запрещены.
3. Пересечения у одного менеджера запрещены. Соседние слоты
   (10:00–11:00 и 11:00–12:00) не конфликтуют.
4. У одной компании не может быть двух активных пересекающихся встреч,
   даже с разными менеджерами.
5. Звонок `meeting_set` обязан ссылаться на активную встречу этой компании
   (`meeting_id`), иначе 422.
6. Перенос не теряет историю: `original_start_time` неизменен, а каждое
   действие пишется в `meeting_events` (`created`, `rescheduled`, `cancelled`)
   и отдаётся в `GET /meetings/{id}` и в ответах на создание/изменение.
7. Все отказы обрабатываются явно и возвращают 4xx с понятным сообщением,
   без 500.

Время принимается и отдаётся в UTC (ISO 8601, `Z`). Входные datetime обязаны
содержать часовой пояс; naive-значение отклоняется. Рабочие часы проверяются
после перевода в `Asia/Almaty`.

## Примеры запросов

Полный сценарий — в [`examples/requests.http`](examples/requests.http)
(совместим с VS Code REST Client / JetBrains HTTP Client).

Быстрый пример:

```bash
curl -s http://localhost:8000/companies \
  -H 'Content-Type: application/json' \
  -d '{"name":"ТОО Ромашка","bin":"123456789012","phone":"+7 777 123 45 67"}'

# Понедельник 10:00 Almaty = 05:00 UTC
curl -s http://localhost:8000/meetings \
  -H 'Content-Type: application/json' \
  -d '{"company_id":1,"manager_id":1,"start_time":"2027-03-15T05:00:00Z"}'
```

## Как обеспечена целостность

- Проверка пересечений и вставка выполняются в одной транзакции
  (`BEGIN IMMEDIATE`), поэтому параллельные запросы на SQLite сериализуются.
- Те же ограничения продублированы триггерами в БД: двойная бронь не
  появится даже при вставке в обход API, а ошибка триггера превращается в 409.
- Подробнее про поведение под нагрузкой — в [REFLECTION.md](REFLECTION.md).

## Тесты (10)

- граница рабочего дня: 09:00 и 17:00 разрешены, 17:30, 08:30, суббота и
  naive-время отклонены;
- пересечение у менеджера и разрешённые соседние слоты;
- двойная активная встреча компании с разными менеджерами;
- `meeting_set` без встречи / с чужой встречей / с корректной встречей;
- перенос с сохранением `original_start_time` и полной истории, отмена;
- конфликт при переносе не меняет встречу;
- фильтр и пагинация компаний;
- расписание на день без отменённых встреч;
- триггер БД блокирует прямую вставку пересечения;
- параллельная бронь одного слота: ровно один 201, остальные 409.
